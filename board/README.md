# board — спинной мозг на плате пылесоса

`body.c` — единственная программа, которую Братан запускает на родной плате робота-пылесоса Xiaomi STYTJ02YM (платформа CRL-200S: Allwinner A33, 4×Cortex-A7 1,2 ГГц, 512 МБ, Linux; моторы и датчики обслуживает MCU GD32).
Один процесс на C без зависимостей владеет обоими UART, держит контур 50 Гц и отдаёт телефону одометрию и сканы лидара по TCP.

Родные службы уборки остановлены. Программа никогда не шлёт команды пылесоса, щёток, воды и управления питанием (`body.c:624`).

## Сборка и запуск

```bash
cc -O2 -std=c11 -Wall -Wextra -Werror body.c -lm -o body
./body --self-test
./body --key /path/to/key --calibration body-calibration.txt
```

| Опция | По умолчанию | Что |
|---|---|---|
| `--serial` | `/dev/ttyS3` | UART к GD32, 115200 8N1 |
| `--lidar` | `/dev/ttyS1` | UART лидара Delta-2D (`-` — без лидара) |
| `--port` | `8800` | TCP-порт для телефона |
| `--key` | обязательно | файл с ключом: 64 hex-символа |
| `--calibration` | встроенная | коэффициенты колёс, гироскопа, ограничения |
| `--inhibit-motion` | выкл. | стендовый режим: колёса заблокированы на весь срок жизни процесса |
| `--motion-not-before` | — | unix-время, раньше которого движение запрещено |
| `--self-test` | — | проверка разбора пакетов, порчи, переполнения, порядка команд |

Второй экземпляр не запустится: эксклюзивный `flock` на `/tmp/robotbrain-body.lock`.

## Контур 50 Гц

Главный цикл — `poll()` по четырём дескрипторам: сервер, GD32, лидар, клиент (`body.c:627`).
Каждые 20 мс `heartbeat()`:

- шлёт GD32 скорости колёс (режим `0x67`, две i32) с ограничением ускорения, а не торможения;
- поворот на месте компенсирует по гироскопу: медленные колёса дотягиваются до измеренной скорости рысканья;
- удерживает курс, если телефон попросил `hold`;
- включает навигационный режим MCU (`0x65`) и питание лидара только на переходах: повторное включение сбрасывает Delta-2D в режим «только здоровье».

Линейная скорость ограничена ±0,24 м/с в самой точке записи в моторы (`body.c:147`).

## Безопасность без телефона

- Нет команды дольше `command_timeout` (0,75 с по умолчанию) — колёса стоят.
- Нет команды 5 с — гаснет лидар, чтобы зависший телефон не посадил батарею на базе.
- Бампер и ИК обрабатываются на плате и уходят телефону в каждом кадре.
- Новый TCP-клиент не принимается, пока жив старый; неверная строка закрывает соединение.

## Протокол с телефоном

TCP, строки ASCII через `\n`, `TCP_NODELAY`. Первая строка — `AUTH <ключ>`. Дальше телефон шлёт каждые 40 мс, пока едет, и раз в секунду на стоянке (`brain/bratan/body/link.py`):

```
SET <seq> <v м/с> <w рад/с> <hold 0|1> <heading рад> <lidar_pwm 0..100>
STOP <seq>
```

`seq` строго растёт: устаревшая команда отбрасывается.
Плата отвечает JSON-строками:

- `{"type":"body", ...}` — 50 раз в секунду: энкодеры, одометрия `[x, y, θ]`, пройденный путь, скорости, смещение гироскопа, бампер, ИК, кнопки, `docked`, `charging`, напряжение, режимы;
- `{"type":"scan", ...}` — каждый оборот лидара: дальности и качество.

## Лидар Delta-2D

Пакет покрывает сектор 22,5° (25 отсчётов). Контрольная сумма — сумма байтов; проверена на 3 400+ подряд реальных пакетах без расхождений, битые пакеты отбрасываются.
Ноль Delta-2D смотрит назад, углы идут по часовой: плата пересчитывает их в кадр LaserScan как `π − angle`. Поворот крепления, 1,5062 рад (≈86°), применяется на телефоне.

## Откуда протокол

Формат пакетов GD32 и Delta-2D сверен с открытой документацией CRL-200S из проекта [VacuumTiger / sangam-io](https://github.com/codetiger/VacuumTiger/tree/main/sangam-io/src/devices/crl200s): `gd32/packet.rs`, `gd32/reader.rs`, `gd32/heartbeat.rs`, `delta2d/protocol.rs`.
Реализация написана независимо: код демона, его настройки и масштабы моторов не копировались.
Рут пылесоса — по инструкциям сообщества для этой ревизии; восьмая ревизия при попытке рута превращается в кирпич.
