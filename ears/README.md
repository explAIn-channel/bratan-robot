# ears — микрофонная решётка на ESP32

Прошивка `ushi-24` для ESP32 (NodeMCU-32S) и трёх микрофонов INMP441. Даёт роботу направление на звук и речь издалека, а телефону — материал для пространственного «нуля» на собственный голос робота.

## Железо

| Сигнал | GPIO |
|---|---|
| SCK (общий для двух шин) | 26 |
| WS (общий) | 25 |
| SD1 — I2S0, M1 слева / M2 справа | 33 |
| SD2 — I2S1, M3 слева / M4 справа | 32 |
| LED (всегда выключен) | 2 |

Микрофоны питаются от 3,3 В; L/R каждого задаёт слот. Используются слоты 0, 2, 3 (M1 спереди, M2 и M3 по бокам), M4 — запас.
Пошаговая 3D-схема проводки — [`provodka-bratana.html`](provodka-bratana.html), место в корпусе — [`korpus/index.html`](korpus/index.html) (открывать через локальный http-сервер из корня репозитория).

## Аудио

- I2S0 — master, I2S1 — slave на том же такте; обе шины стартуют в одной критической секции, старые DMA-буферы сбрасываются.
- 16 кГц, слоты 32 бит (24 бит данных), 8 DMA-буферов × 256 кадров, блок 16 мс.
- ФВЧ Баттерворта 2-го порядка 60 Гц, перевод 24→16 бит с насыщением, IMA-ADPCM 4 бит.
- Задача аудио — приоритет 22 на ядре 1; самодиагностика каждого слота (ok / spill / ghost / none / float / gaps / noise / hop).

## Сеть

UDP 5771, до четырёх подписчиков; подписку нужно продлевать раньше чем через 3 с.

| Команда | Ответ |
|---|---|
| `ping` | JSON: версия, аптайм, RSSI, потери, память, подписчики, BLE |
| `sub` / `subv [слот]` / `suba` / `subm [слоты]` / `unsub` | сырой поток / один канал PCM16 / один канал ADPCM / несколько каналов ADPCM / отписка |
| `health`, `pins`, `raw`, `restart` | диагностика |

Пакет `BRV1`/`BRM1`: заголовок 20 байт — тег, `seq` u32, первый кадр u32, число кадров u16 (512 = 32 мс), кодек u8 (0 PCM16, 1 ADPCM), слот или маска u8, эпоха u16, число каналов u8, байт выравнивания. Блок ADPCM: предсказание i16, индекс шага u8, байт выравнивания, 256 байт полубайтов. Три канала ≈ 25 КБ/с.

BLE GATT: сервис `6b9c0001-3f6e-4f4b-9a54-6272617461e1`, NOTIFY `…0002`, запись ключа `…0003`; MTU 517. Поток идёт только соединению, записавшему верный токен, неверный — разрыв. Пакеты режутся на куски: бит 7 первого байта — начало пакета, затем длина u16.

## Надёжность

- Wi-Fi: настройка через точку `Bratan-Ushi` (WiFiManager) или WPS; переподключение через 15 с, перезапуск связи через 60 с, перезагрузка через 10 мин офлайн.
- BLE: шесть «молчащих» соединений подряд после 10 мин работы — перезагрузка.
- OTA: пароль из сборки (не короче 8 символов); новая прошивка подтверждается, только если 60 с держит Wi-Fi, иначе откат.

## Прошивка

```bash
python tools/flash.py usb      # первый раз, по кабелю
python tools/flash.py ota      # дальше по Wi-Fi, ждёт возвращения платы
python tools/flash.py status
```

Пароль OTA и токен BLE создаются один раз в `.ota-pass` и `.ble-token` (в git не попадают) и вшиваются через переменные `USHI_OTA_PASS`, `USHI_BLE_TOKEN`.
